🧱 CS 499 Enhancement Narrative: Software Design & Engineering Focus

For the software design and engineering portion of my ePortfolio, I focused on improving the structure, modularity, and maintainability of a project originally built during CS 340. The artifact, originally a single script handling all database logic and UI rendering, lacked separation of concerns, had hardcoded configuration values, and did not follow any defined module structure. My enhancements brought the code in line with modern engineering standards by introducing object-oriented design, environment-based configuration, and a directory structure that promotes scalability.

🗂️ Modular Directory Structure

The original project existed as just two files. In the enhanced version, I introduced a professional-grade folder structure: 

capstone-project/
├── src/
│   ├── AnimalShelterCRUD.py
│   ├── AnimalShelterDAO.py
│   └── ProjectTwoDashboard.py
├── config/
│   └── .env
├── assets/
├── data/
├── old-code/

This separates the backend logic (CRUD and DAO layers), the dashboard (Dash UI), and externalized configs, supporting better code reuse and maintenance.

💡 Before: CRUD Logic Hardcoded in Dashboard

Originally, database operations were embedded inside the dashboard logic:

# Old (inside dashboard)
client = MongoClient("mongodb://localhost:27017/")
db = client["animal_shelter"]
result = db.animals.find({})

This tightly coupled the application layers, made testing difficult, and exposed the connection logic directly in the UI.

✅ After: Encapsulated with Object-Oriented CRUD Class

I rewrote this using a dedicated AnimalShelterCRUD class in AnimalShelterCRUD.py:

# AnimalShelterCRUD.py
class AnimalShelterCRUD:
    def __init__(self, db_connection, collection_name="animals"):
        self.collection = db_connection.get_database()[collection_name]

    def read(self, query={}, limit=100):
        return list(self.collection.find(query).limit(limit))

    def create(self, document):
        return self.collection.insert_one(document)

This class abstracts all database logic and safely limits queries. It's easily testable and reusable across multiple interfaces.

🔐 Secure Configuration via Environment Variables

Previously, database details were hardcoded, like this:

# Old
client = MongoClient("mongodb://localhost:27017/")

I enhanced this by using dotenv for configuration:

# MongoDBConnection.py
from dotenv import load_dotenv
load_dotenv()
uri = os.getenv("MONGO_URI")
db = os.getenv("MONGO_DB_NAME")

This aligns with secure coding practices and keeps sensitive info out of version control.

📊 Result: Loosely Coupled, Testable, and Scalable

Each file now has a focused responsibility:

  • AnimalShelterCRUD.py: Handles create/read/update/delete
  • AnimalShelterDAO.py: Acts as an interface between the UI and the database
  • ProjectTwoDashboard.py: Solely manages Dash app layout and callbacks

The result is a clean separation of concerns that makes future expansion (e.g., switching to PostgreSQL or adding unit tests) straightforward.

🧠 What I Learned

Refactoring this code helped reinforce the importance of modularity and abstraction. I realized how coupling can sneak into small projects and scale poorly if not addressed early. The experience also improved my confidence in writing production-quality Python and aligning code structure with industry best practices like SOLID principles.
