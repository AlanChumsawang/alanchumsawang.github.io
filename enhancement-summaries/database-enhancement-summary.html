💾 CS 499 Enhancement Narrative: Database Focus

The selected artifact is a MongoDB-backed application I built, which allows users to perform CRUD (Create, Read, Update, Delete) operations on animal shelter records. It was created in a previous course as part of a CRUD-focused project. However, I have revisited it here to make meaningful backend improvements, especially how the database is handled. The original setup worked, but the database logic was tightly coupled to the main application logic, making it hard to maintain and extend.

🧠 Original Database Logic: Tightly Coupled

In the original implementation, the database connection logic was embedded directly into the main application code:

# Old: Hardcoded database connection
client = MongoClient("mongodb://localhost:27017/")
db = client["animal_shelter"]
collection = db["animals"]

This approach:

  • Violated separation of concerns by mixing database logic with application logic
  • Made the code harder to test and maintain
  • Exposed sensitive configuration details in the source code

✅ Refactored: Modular Database Connection

To address these issues, I refactored the database logic into a dedicated MongoDBConnection class. This class handles all connection details and securely retrieves configuration from environment variables:

# New: Modular database connection
from pymongo import MongoClient
import os

class MongoDBConnection:
    def __init__(self, host, port, db_name):
        self.client = MongoClient(f"mongodb://{host}:{port}")
        self.db = self.client[db_name]

    def get_collection(self, collection_name):
        return self.db[collection_name]

This refactor improved the code by:

  • Separating database logic into its own reusable class
  • Securing sensitive details using environment variables
  • Making the application more modular and testable

🔒 Secure Configuration with Environment Variables

Previously, database details were hardcoded, which posed a security risk. I enhanced this by using environment variables to store sensitive information:

# Secure configuration using dotenv
from dotenv import load_dotenv
load_dotenv()

host = os.getenv("MONGO_HOST")
port = os.getenv("MONGO_PORT")
db_name = os.getenv("MONGO_DB_NAME")

This approach aligns with secure coding practices and ensures sensitive information is not exposed in version control.

📊 Result: Reliable, Scalable, and Testable

The refactored database logic is now:

  • Loosely coupled, making it easier to maintain and extend
  • Secure, with sensitive details stored in environment variables
  • Testable, as the database connection can be mocked during unit tests

These changes demonstrate my ability to improve backend architecture and align with industry best practices.

🧠 What I Learned

Throughout the enhancement process, I learned how much cleaner and more testable code becomes when database logic is pulled into its class. I also identified how early validation can help catch issues at the point of input, reducing potential bugs downstream. One bigger challenge was ensuring the validation logic did not over-restrict input, especially when working with unpredictable JSON-based data. In the end, these changes helped me build a more stable application and deepened my confidence in building production-quality backend systems.
